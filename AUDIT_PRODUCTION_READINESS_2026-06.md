## Verification gaps — what this audit could NOT confirm

This was a static source trace: no app ran on a device/emulator and no Gradle build was executed. The items below cap confidence and must be closed before release.

- RUNTIME-WIDE: Every one of the 27 areas explicitly states it could not run on a device/emulator and did not run Gradle builds. The entire audit is a static source trace. No finding has been confirmed against observed behavior, and no claim that 'compiles/wires correctly' was checked by even a compile-only gate (the CLAUDE.md-blessed `:composeApp:compileKotlinDesktop/...Android/...IosSimulatorArm64 --offline` was never executed). This is the single largest coverage gap and it caps confidence on every 'STRONG/GOOD health' verdict.
- SOURCES (12 generic pilots) — UNVERIFIED CORRECTNESS: The Sources area states selector/JSONPath correctness for all 12 piloted sources (Azora, Mangamello(+Plus), SwatManga, Lekmanga, Team X, DilarV2, 3asq, Demonicscans, Mangabuddy, Zazamanga, Tapas) in BundledSourcesConfig.kt is 'unverifiable by reading alone' and the configs are owner-WIP dated 2026-06-07. No live network call, no CF-solved cf_clearance run. The generic-engine home/featured/details/pages output was never traced into sources_repositry (forbidden path). This means the headline 'generic engine is live in production' claim is verified for wiring but NOT for producing correct manga data for any source.
- SOURCES — POSSIBLE OVER-FILTER NOT ADJUDICATED: GenericSourceClient.isBlacklistedByGenre uses case-insensitive substring `contains` for feed filtering while native BaseManga.hasBlacklistedGenre uses exact-set membership. The auditor explicitly LEFT THIS OUT of findings because it could not be confirmed without per-source legacy blackListGenres values + live data. This is an un-adjudicated potential parity bug (could silently over-filter generic-pilot feeds), not just an unverified claim.
- CBZ/WEBP iOS — NO NATIVE ROUND-TRIP PROOF: The whole iOS CBZ pipeline rests on SkiaWebpEncoder behavior on iosArm64 (asserted only indirectly via the Desktop test using the same org.jetbrains.skia API) and on a hand-rolled StoreZipWriter whose LE-header/CRC32 correctness was verified by reading bytes against the ZIP APPNOTE but never executed against okio.openZip in a Native test. The auditor's own note: an iOS-device smoke test of createCbzWithSplitting + read-back is 'the only total proof for the iOS target.' Multiple confirmed 'CbzWriter is a real WebP writer' findings depend on this unproven iOS path.
- PERSISTENCE (Desktop headers overflow) — THRESHOLD NOT DEMONSTRATED: The confirmed [persistence/medium] Desktop java.util.prefs 8KB value-limit overflow on the aggregated HEADERS_MAP_JSON is reasoned from 41 sources writing one unguarded JSON value; the actual overflow point needs a populated store, and the auditor did not inspect multiplatform-settings 1.3.0 bytecode to confirm PreferencesSettings.putString propagates (rather than swallows) the IllegalArgumentException. Whether this throws, is caught silently, or corrupts the store at runtime is unconfirmed — directly affects the medium severity.
- COMPLAINT/FEEDBACK (iOS/Desktop) — BACKEND-DEPENDENT SILENT-EMPTY RISK: The REST getComplaintsByUser uses a Firestore composite OR filter that may require a composite index; absent it the call returns HTTP 400 which is caught and turned into emptyList(), silently showing 'no complaints' on iOS/Desktop. This depends on Firestore console index config + security rules (public unauthenticated API key) that cannot be read from source. No device/simulator Firestore round-trip was performed. A real-but-backend-gated data-visibility bug is plausible and uncovered.
- STATISTICS — OVER-COUNT MAGNITUDE UNMEASURED + ZERO TESTS: The confirmed [statistics/medium] 'KMP counts backgrounded time as reading time' is reasoned from DisposableEffect(Unit) having no lifecycle observer; the actual over-count magnitude and per-platform background/foreground composition-disposal semantics (Android stop-not-destroy, iOS background, Desktop minimize) were not measured at runtime. Additionally there are NO unit tests for StatisticsViewModel / ReadingStatisticsRepositoryImpl / ReadingSessionRepositoryImpl in :presentation or :data.
- DI GRAPH — iOS/DESKTOP KOIN NEVER EXERCISED: Confirmed [di-graph/medium]: only Android platformModule() is registration/resolution-tested. iOS and Desktop Koin graphs were never started, and the JVM verify() check is reflection-only and (per its own KDoc) walks only the bound interface type, NOT impl-ctor deps — so a drifted ctor dependency on any platform would pass the test and was caught only by manual reading. First-resolve crashes on a real iOS simulator / Desktop JVM (e.g. singletons calling NSBundle/androidContext()/java.util.prefs) remain possible and untested. This undercuts every other area's 'DI fully wired, no missing actuals' assurance.
- IMAGE LOADING (AVIF on iOS/Desktop) — RENDER FAILURE NOT OBSERVED: Confirmed [image-loading/high] 'AVIF fails to decode on iOS/Desktop' and [image-loading/medium] cover header host-match gap are both asserted from source + native comparison, not observed at runtime. The cover-auth gap specifically depends on which sources are CF-protected with a CDN host differing from base host — and those per-source CDN configs live in sources_repositry (read-only, not audited). So the high/medium severities rest on unobserved rendering + un-enumerated per-source configs.
- READER — STREAMING-SOURCE RESUME (Prochan) CLAMP UNCONFIRMED: The auditor flagged but could not confirm that for a streaming source whose first cumulative emission has fewer pages than the saved resume index, the VM clamps currentPageIndex to the smaller lastIndex and loses the resume position on the first frame. Real emission sizes were not observable (sources_repositry forbidden). This is a potential per-source data-loss-of-position bug left unadjudicated.
- OFFLINE/DOWNLOAD — ENQUEUED-WHILE-OFFLINE BEHAVIOR UNKNOWN: For the confirmed [offline/medium] dropped connectivity gate, the auditor could not determine whether an enqueued download while offline fails fast with a surfaced error, sits QUEUED, or retries — which is exactly what determines whether the dropped gate is cosmetic or leaves a confusing stuck-queue. This requires running the Android WorkManager vs iOS/Desktop coroutine engines. The download-engine internals (DownloadWorkerV2 / ChapterDownloadService / CoroutineDownloadRepositoryImpl) were only skimmed for offline failure handling, not fully audited.
- CBZ AVIF PAGE-DROP ON ANDROID BULK-CONVERT — NOT FILED, MATCHES-NATIVE ASSUMPTION UNVERIFIED: The Android bulk-convert path (AndroidCbzWriter/native CbzManager via BitmapFactory) silently DROPS AVIF pages (returns null), while download-time OptimizedCbzManager transcodes them. - ERROR/EMPTY-STATE CRASH HAZARDS — REALIZATION UNPROVEN: The confirmed History-collector missing-.catch{} crash and the systemic bare-viewModelScope.launch{} hazard are confirmed by code reading but their realization depends on an underlying Room/DataStore write actually throwing (rare) — needs a corrupt-DB device repro to prove the process-crash consequence and confirm the Android-vs-iOS/Desktop crash divergence.
- PLATFORM SERVICES (Analytics/AdMob) — NATIVE EVENT SET NOT ENUMERATED: The confirmed [platform-services/medium] 'logEvent never called' was established by grep, but the auditor did not enumerate native-app's full analytics event set beyond app_open/manga_open (events in fragments not opened were missed). Also Desktop/iOS hosts (Main.kt, iosApp) were not opened to confirm they lack a MainActivity-equivalent flow — the Update/Review/Consent 'Android-only' conclusion is inferred, not verified, for the non-Android hosts.
- THEME/LANGUAGE/RTL — LIVE LOCALE SWITCH UNOBSERVED ON 3 PLATFORMS: Whether Android's LocalConfiguration override actually re-resolves compose-resources strings live under a ComponentActivity, whether AppCompatDelegate.setApplicationLocales() throws under a non-AppCompat host, whether iOS picks up AppleLanguages on relaunch, and whether Desktop's keyed recomposition re-reads strings — all four were verified by code only and flagged as needing device confirmation. RTL mirroring on a real Arabic device was not exercised.

Cross-locale plural/relative-time rendering (items-count, h_m, relative timestamps) is unverified. A missing/untranslated key in a non-sampled locale would go undetected.
- WEBVIEW / CLOUDFLARE SOLVER SUBSYSTEM — NOT AUDITED AS ITS OWN AREA: Several areas (Sources, Image loading, Details, Reader, Error-states) repeatedly defer the WebView cookie/cf_clearance capture (setCookie/getCookie/ensureSiteInitialized->initSite) and the per-platform WebViewHost solver to a 'WebView/Cloudflare area' that does not appear as a covered area in this audit. - NAVIGATION STATE RESTORATION — PROCESS-DEATH ROUND-TRIP UNPROVEN: Whether the JetBrains androidx-navigation 2.9.2 port reliably (de)serializes List<String>? / List<String> nav args (Screen.ChapterImagesFragment.paths, Screen.MangaDetailsRework.genres) across process-death restoration without a custom typeMap was not proven on a device. This means per-source scraper parsing correctness, per-source defaultHeaders hydration timing, per-source CDN/blacklist configs, and the exact native runtime bodies (e.g. response.body().toString() vs bodyAsText()) are systematically out of scope — yet several confirmed findings (sources/high URL propagation, image-loading covers, reader resume) have severities that hinge on data living in those paths.
