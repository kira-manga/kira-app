# Resource Migration Report — Phase 10

> Mandatory output per Phase 10 / Section 40 of `MIGRATION_PROMPT.md`.

## Per-resource-type strategy

| Source path | Destination | Rationale |
|---|---|---|
| `app/src/main/res/values/strings.xml` (~800 strings, default English) | `composeApp/src/commonMain/composeResources/values/strings.xml` | Compose-resources picks up the same XML schema as Android resources. |
| `app/src/main/res/values-ar/strings.xml` | `composeApp/.../composeResources/values-ar/strings.xml` | RTL preserved via Compose-MP's `LocalLayoutDirection`. |
| `app/src/main/res/values-{de,es,fr,in,it,ja,pt,ru,tr}/strings.xml` | `composeApp/.../composeResources/values-<lang>/strings.xml` | Direct copy. |
| `app/src/main/res/values-night/` (dark theme overrides) | NOT copied — folded into `composeApp/src/commonMain/kotlin/.../theme/Theme.kt` `DarkColorScheme` (Compose handles theming in code) | Resolved F1: values-night holds only `colors.xml` + `themes.xml`, both Material-XML constructs that Compose-MP doesn't consume. |
| `app/src/main/res/values-v26/` | `app/src/main/res/values-v26/` (already copied in Phase 3) | Android API 26+ system feature only. |
| `app/src/main/res/drawable/*.xml` (vector drawables, ~80 files) | `composeApp/.../composeResources/drawable/` | CMP supports XML vector drawables natively. Already copied (Phase 3) — Phase 10 moves the cross-platform ones to composeResources. |
| `app/src/main/res/drawable/*.png` / `.jpg` / `.webp` / `.jpeg` (bitmap drawables — Plus18memes, launcher previews, new_pr_*, etc.) | `composeApp/.../composeResources/drawable/` | CMP supports bitmap drawables via `painterResource`. |
| `app/src/main/res/mipmap-*/ic_launcher*` | `app/src/main/res/mipmap-*/` (stays Android-only) | Launcher icons are Android-specific. iOS gets its own asset catalog in Phase 12. Desktop uses an .icns/.ico in Phase 13. |
| `app/src/main/res/font/` | `composeApp/.../composeResources/font/` | CMP supports TTF/OTF fonts via `Font(Res.font.<name>)`. |
| `app/src/main/res/raw/` | `composeApp/.../composeResources/files/` | Access via `Res.readBytes("files/<name>")`. |
| `app/src/main/res/xml/{file_paths, network_security_config, data_extraction_rules, backup_rules}.xml` | `app/src/main/res/xml/` (already copied) | Android system descriptors. |
| `app/src/main/res/layout/` (XML View layouts for ViewBinding) | Audit in Phase 10; if unused by composables, drop. Otherwise stay Android-only. | ViewBinding is Android-only. |

## Access pattern

After move, access becomes:

```kotlin
import me.manga.kira.composeapp.generated.resources.Res
import me.manga.kira.composeapp.generated.resources.app_name
import me.manga.kira.composeapp.generated.resources.ic_launcher_foreground

@Composable
fun Foo() {
    Text(stringResource(Res.string.app_name))
    Image(painterResource(Res.drawable.ic_launcher_foreground), contentDescription = null)
}
```

The `Res` class is generated by the Compose Resources plugin under the package configured in `composeApp/build.gradle.kts:99` (corrected to `me.manga.kira.composeapp.generated.resources` in commit `90f1a85` — see `OLD_WORK_AUDIT_FINDINGS.md` H-1).

## Decisions logged

1. **`values-v26/` stays Android-only** — contains theme overlays for API 26+ adaptive-icon support. CMP doesn't expose API-level resource qualifiers (those are Android-runtime concerns).
2. **Launcher icons stay in `app/res/mipmap-*/`** — Android's `<application android:icon>` reference resolves at the Android resource layer, not via compose-resources.
3. **ViewBinding-targeted `layout/` XMLs** — Phase 10 audit pending. Source had `viewBinding = true` in build features and `androidx.compose.ui:ui-viewbinding:1.6.0-rc01` as an explicit dependency, suggesting at least one composable wraps a View. If audit finds none, drop the dep + the layout files. If audit finds users, keep on Android only.
